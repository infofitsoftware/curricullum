# Chapter 3: Defining Product Features

## Learning Objectives

After this chapter you should be able to:

1. Turn user stories into a feature list.
2. Separate must-have features from nice-to-have features.
3. Defend why something is delayed (Not-now).
4. Keep scope small enough to ship.

---

## 1. Why This Matters

Beginners fail by building everything:

chat + payments + AI + maps + admin + notifications…

A product-aware developer asks:

> “What is required for the user to complete the main job?”

That is your **must-have** set.

---

## 2. Core Concepts

### Feature

**Definition:** A product capability the user can notice and use.

Example features: registration form, confirmation message, attendee list.

### Must-have features

**Definition:** Features without which the main user job fails.

### Nice-to-have features

**Definition:** Features that improve experience but can wait until after MVP works.

### Quick test

Ask for each feature:

1. If we remove this, can the user still complete the core job?  
   * No → must-have  
   * Yes → nice-to-have / later  

---

## 3. Interactive Class Flow

### Warm-up debate (8 min)
Teacher: “For a salon booking MVP, is online payment must-have?”  
Students argue both sides.  
Likely classroom conclusion: often nice-to-have if phone confirmation works.

### Activity A (15 min) — Feature dump
From your user stories, list 10 possible features quickly. No judging.

### Activity B (20 min) — Sort the list
Make three columns on paper/board:

`Must-have | Nice-to-have | Not now`

Rules:

* Must-have: max **5** for this course MVP start  
* Every must-have must map to at least one user story  
* If students argue, use the “core job” test  

### Activity C (10 min) — Defend one cut
Each student says one feature they moved to Not-now and why.

Teacher reinforces: cutting is professional.

---

## 4. Relatable Examples

### Campus event registration
**Must-have:** event details page, register form, thank-you/confirmation, admin list  
**Nice-to-have:** email reminders, waitlist, QR check-in  
**Not now:** payments, chat, AI recommendations

### Tuition fee tracker
**Must-have:** add fee item, due date, mark paid/unpaid, list view  
**Nice-to-have:** SMS alerts, receipts upload  
**Not now:** UPI autopay, multi-institute marketplace

---

## 5. Common Mistakes

1. 15 must-haves.  
2. Must-haves based on “competitor has it.”  
3. Nice-to-haves sneaking back into week-1 build.  
4. Features with no user story.

---

## 6. Exit Ticket

Submit your three-column feature list + one sentence:

> “My product’s core job is ___.”
