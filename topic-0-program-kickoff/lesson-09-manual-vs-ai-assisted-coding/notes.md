# Lesson 09 — Manual Coding vs AI-Assisted Coding Rules

**Duration:** 45 minutes  
**Prerequisite:** Lessons 07–08  
**Goal:** Students know the bootcamp’s official rules for when to code manually, when to use AI, and how to pass skill checks and interviews.

---

## 1. Why we need rules

AI can write code in seconds. Without rules, students **skip learning** and fail:

- **No-AI skill checks** in this course  
- **Technical interviews** (live coding, explain your project)  
- **First week on the job** when AI isn’t allowed on internal systems  

**Goal:** Use AI like a **senior teammate**, not a **replacement for your brain**.

---

## 2. Two modes of work

| Mode | Definition | When |
|------|------------|------|
| **Manual coding** | You type logic yourself, with docs/Google allowed | New concepts, assessments, core loops & APIs |
| **AI-assisted coding** | AI generates/edits; you review, run, fix, explain | Boilerplate, styling polish, refactors, debugging help |

**Both are professional** — the skill is knowing **which mode** and **when**.

**Real-life analogy — driving test:**  
You must drive without assistance to prove you can; after license, GPS helps on new roads.

---

## 3. Bootcamp rules (official)

### Rule 1 — Manual first on new topics  
First time you see HTML forms, React `useState`, FastAPI routes, SQL queries: **try yourself** (or follow lesson steps) before AI generates the solution.

### Rule 2 — AI suggests, you decide  
Read every generated line. If you can’t explain it in plain language, **don’t commit it**.

### Rule 3 — Always run and test  
Browser, terminal, API client — **no submit without proof it works**.

### Rule 4 — No AI during marked “no-AI” checks  
Skill checks are labeled clearly. Violation = redo + academic integrity conversation.

### Rule 5 — Commit messages are yours  
Describe **what you changed and why** — not “AI update.”

### Rule 6 — No secrets in AI chats  
Never paste production passwords, `.env` contents, client private data.

### Rule 7 — Portfolio honesty  
You may use AI to assist; you must **own** the project and demo it live.

### Rule 8 — Stuck protocol  
1. Read the error message  
2. Check lesson notes / docs (15 min)  
3. Search the error text  
4. Ask AI with **CCTO prompt** + code snippet  
5. Ask instructor/peer if still blocked  

---

## 4. What “manual” means in practice

**Manual does NOT mean:**

- No Google  
- No documentation  
- No Stack Overflow  

**Manual DOES mean:**

- **You** write the core logic lines  
- **You** choose structure and variable names  
- **You** can reproduce a simplified version in an interview  

**Example — BookEase landing (Week 2):**

| Manual | AI-assisted |
|--------|-------------|
| You write `<header>`, `<main>`, `<footer>` structure | AI suggests better semantic tags; you approve |
| You type first draft of hero text | AI improves copy; you edit tone |
| Skill check: build form **without** Cursor AI tab | Homework: polish CSS with AI after manual draft |

---

## 5. What “AI-assisted” means in practice

**Good uses:**

- “Generate responsive grid for 3 feature cards — I’ll adjust colors.”  
- “Why is this flexbox not centering?” + screenshot/CSS paste  
- “Convert this JS file to TypeScript with basic types.”  
- “Write pytest skeleton; I’ll fill assertions.”  

**Bad uses:**

- “Build entire BookEase backend” on day 3 with zero reading  
- Submitting AI code for no-AI quiz  
- Changing code you don’t understand because “it works on my machine once”  

---

## 6. Red flags — stop and learn

Pause AI and go manual if:

- You can’t explain what a function does  
- You copy imports you don’t recognize  
- Tests fail and you “fix” by asking AI in a loop without reading errors  
- Teammate asks “why this approach?” and you freeze  

**Interview red flag:**  
“AI wrote it” is not an answer to “walk me through your authentication flow.”

---

## 7. Weekly workflow template

```
Monday–Tuesday: Learn concept + manual exercises
Wednesday:        AI-assisted improvement on YOUR draft
Thursday:         Debug lab (AI allowed with stuck protocol)
Friday:           Mix — project work + reflection
Skill check week: Manual only (announced)
```

**Reflection question (end of week):**  
“What did I write manually? What did AI improve? What did I fix myself?”

---

## 8. Class activity — scenario cards (15 min)

Students draw a scenario and answer: **Manual, AI-assisted, or Not allowed?**

1. Week 2 HTML skill check in class. → **Manual only**  
2. Styling hero section after you wrote HTML. → **AI-assisted OK**  
3. Copy entire peer’s GitHub repo. → **Not allowed (integrity)**  
4. Paste API key so AI can test payment. → **Not allowed (secrets)**  
5. Explain `for` loop homework first try. → **Manual first**  
6. Generate README for your repo. → **AI-assisted OK if reviewed**  

Discuss borderline cases as a class.

---

## 9. Signing the developer mindset (optional pledge)

> I will use AI to move faster, not to skip learning.  
> I will run and understand code before I submit.  
> I will follow no-AI rules on skill checks.  
> I will build a portfolio I can demo and explain in an interview.

---

## 10. Key takeaways

1. **Manual** proves skill; **AI-assisted** speeds polish — both matter.  
2. Follow the **8 bootcamp rules** every week.  
3. **Stuck protocol** before asking AI blindly.  
4. Interviews test **you**, not your chatbot.  
5. Human + AI developer = **hireable in 2026**.
